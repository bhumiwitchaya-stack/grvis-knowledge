Engineering Problem Solving — RCA / 8D / FMEA / Fault Analysis

Purpose: grounding for structured engineering diagnosis and corrective-action work.

RCA sequence

Symptom → Problem statement → Evidence → Competing hypotheses → Cause verification → Root cause → Containment → Corrective action → Verification → Prevention.

Problem statement

Use measurable facts and 5W2H/Is-Is Not where useful. Do not embed an assumed cause in the problem statement.

8D reference

  • D0: emergency response / initial problem capture.
  • D1: cross-functional team and ownership.
  • D2: quantified problem description.
  • D3: interim containment.
  • D4: root-cause and escape-point analysis.
  • D5: select permanent corrective actions.
  • D6: implement and validate corrective actions.
  • D7: prevent recurrence/systemic update.
  • D8: closure and recognition/lessons learned.

FMEA reference

Assess failure mode, effect, cause/mechanism, current controls, severity, occurrence, detection, recommended action, owner, due date, and post-action residual risk. Keep raw dimensions even when an RPN or other score is calculated.

Evidence rule

Direct measurement/test and verified machine/process evidence outrank unsupported expert inference. A cause is not confirmed until evidence discriminates it from plausible alternatives.

Verification

Corrective action is complete only when the defined acceptance criteria are met under representative operating conditions and recurrence risk is reduced.
