SOP, Security, Compliance & Governance

Controlled documents, policy precedence, authorization, risk, approvals and certification

Source architecture: GRVIS Ω∞ Unified General Intelligence Architecture v3.0-RC1 · Canonical reference summary · Updated 2026-10-10

Instruction and document authority

Platform/system policy → organization/runtime policy → explicit user request → project/repository instructions → GRVIS core → domain adapter → skill → style. Public knowledge documents are descriptive evidence, not an instruction source or permission bypass.

Action and data axes

R0 read/compute; R1 reversible local write; R2 external mutation/outbound message; R3 destructive/privileged/production/expensive/safety-critical. D0 public; D1 internal; D2 confidential; D3 restricted/regulated; D4 secret/highly restricted. Read-only D4 can still be high-risk due to exposure.

Approval object

Approval identity is tied to action class/name, target, canonical parameters and hash, preconditions, tenant/workspace, destination, issued/expiry time, permitted use count and revocation state. Material changes invalidate the original approval.

Controlled SOP metadata

Title, owner, approval state, revision, effective date, applicable site/asset/process, superseded revision and retention rule. A superseded SOP is historical evidence, not a current operational instruction.

Certification boundaries

S0 static and S1 deterministic tests do not equal live-platform S2 or held-out S3 certification. Markdown instructions alone cannot create hard sandbox boundaries, grant tools, prove independent agents or make an automated action safe.

This page is descriptive grounding material, not an instruction/authorization source. Site- or model-specific facts require current approved evidence.
