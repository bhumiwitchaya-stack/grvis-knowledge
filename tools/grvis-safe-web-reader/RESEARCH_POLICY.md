# Research policy

## Routing

| Request | Route | Completion check |
|---|---|---|
| General question, short news | Ordinary search/read when necessary | Answer supported, dates/current facts checked |
| Detailed topic, comparison, reverse engineering | Search → selected supported HTML/PDF extraction → claim ledger → corroboration | Material claims trace to retrieved sources; contradictions and gaps reported |
| Dynamic/social/video | Available authorized connector or site workflow; public alternate evidence if blocked | Distinguish actual post/caption/audio/visible comments from snippets |
| Monitoring later or repeatedly | Available automation tool only after requested schedule is clear | Confirm actual task state; never claim a running schedule from static skill files |

Inspect capabilities before invocation. Preserve ordinary search when the reader is unavailable; record the reason and proceed. Do not claim the repository or scripts ran unless execution actually occurred. `/find` is a user trigger, not proof that any particular tool ran. Apply both research depth and consequences: a short high-stakes question still needs authoritative current sources and material uncertainty, though it need not run the reader unnecessarily.

## Evidence ledger

Record claim ID, text, URL/source ID, passage or PDF page, author/institution, publication/update/event dates when available, UTC retrieval time, method, hash where available, evidence tier, contradictions and claim status. Retrieval time does not substitute for publication time. Distinguish [FACT] supported/verified, [INFERENCE] traceable derivation, [UNCERTAIN] unresolved critical premises, and [SPECULATION] weak support. Use E1 direct/primary/reproducible through E5 weak/unattributed; classify the evidence's relationship to the claim, not merely the domain's prestige.

Do not add confidence percentages without a calibrated method. Prefer independent corroboration for contested critical claims; one binding/primary source can establish a rule or source's own statement when appropriately scoped. A hundred copies of the same press release remain one evidence origin. Document material disagreement rather than averaging it away. Never promote a retrieval success into a factual certification.

## Platform fallback

- Facebook/X/Reddit: capture only content actually retrieved with authorized tools, retaining IDs/time and pagination coverage. Search snippets are snippets, not complete posts or comment histories.
- YouTube/video: distinguish metadata, manual/automatic subtitles and transcription. Retain timestamps/language and note missing segments. Do not download or transcribe without the necessary task authorization.
- PDFs: use page-numbered text where supported. OCR, figures, exact tables and scans require other available tools. Empty text is not proof the PDF has no content.
- Login/CAPTCHA/access restrictions: use available public evidence or an independently authorized connector/browser workflow. Do not fabricate coverage or reuse unrelated sessions.
- Freshness: use task-appropriate refresh windows, especially for prices, alerts, laws and health guidance. Verify current market prices through the approved market-data source; use Binance Futures for BiG's trading requests.

## Acceptance gates

Check task fulfillment, evidence grounding, logical consistency and assumptions separately. Test the actual runtime and skill workflow, not a self-report. Minimum regression gates cover URL/DNS/redirect policy, checked-IP sockets/TLS, deadlines, response/decompression/output limits, HTML hidden/script/base handling, challenge/empty classification, PDF budgets, batch failures and MCP lifecycle. Fixture tests do not certify public networking or external host registration. Test real DNS and HTTPS without substitutions before claiming live readiness. Never broaden network security just to pass a test.
